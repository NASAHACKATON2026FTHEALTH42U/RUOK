## Getting started

```bash
cd backend
uv sync --all-extras --dev                 # installs dependencies into .venv
uv run uvicorn app.main:app --reload       # API at http://localhost:8000/api/v1
uv run pytest                              # tests
uv run --with ruff ruff check .            # lint (same as CI)
```

- Swagger: <http://localhost:8000/docs>.
- Quick check: `curl -i localhost:8000/api/v1/health`.
- The `backend/ruok.db` database is created automatically at startup. It is in `.gitignore` (as are `-wal` and `-shm`).
- If you change the API (routes, schemas or `description`), regenerate the frontend types: `cd frontend && npm ci && npm run gen:api`. It requires **Node 20** (`mise use -g node@20` or `nvm install 20`). CI fails if `types.gen.ts` is not up to date.

## Core pieces

### Database: SQLite in WAL mode (`app/db.py`)

**WAL** (*Write-Ahead Logging*) is a SQLite journal mode. Instead of modifying `ruok.db` directly, writes are appended to `ruok.db-wal`, and a *checkpoint* flushes them into the DB from time to time.

- **Reads alongside one write at a time:** the dashboard can read while measurements arrive or the link queues messages, without `database is locked` errors.
- **Robustness:** a committed transaction is already in the WAL and is recovered if the process crashes (the *no data loss* principle).
- **Limits:** a single writer at a time (enough here) and the DB must be on a local disk.

`make_engine()` runs `PRAGMA journal_mode=WAL` and `PRAGMA foreign_keys=ON` on **every connection**. The latter is needed because SQLite does not enforce foreign keys unless it is enabled.

Usage in an endpoint (one session per request):

```python
from fastapi import Depends
from sqlmodel import Session
from app.db import get_session

@router.get("/members")
def list_members(session: Session = Depends(get_session)):
    ...
```

`init_db()` imports `app/models.py` and creates any missing tables and indexes (`create_all`: it does not drop or alter existing tables). If you change a table that already exists in your `ruok.db`, delete it (`rm backend/ruok.db*`) so it is recreated; there are no migrations.

### Models (`app/models.py`)

One `SQLModel` class with `table=True` for each table in [data-model.md](data-model.md) §1:

| Group | Models (table) |
|---|---|
| Users and members | `Member` (member), `UserAccount` (user_account), `Device` (device) |
| Measurements | `Measurement` (measurement) |
| Routine and gamification | `Task` (task), `TaskCompletion` (task_completion), `BadgeAward` (badge_award), `Kudos` (kudos) |
| Alerts and check-in | `Alert` (alert), `AlertEvent` (alert_event), `RuokCheck` (ruok_check) |
| Simulated link | `LinkMessage` (link_message), `LinkState` (link_state) |
| Real time and technical | `EventLog` (event_log), `AppState` (app_state) |

Conventions:
- **Dates:** `sa_type=UTCDateTime`. SQLite does not store the time zone; this type converts to UTC on write and returns dates with `tzinfo=UTC` on read. **It rejects naive dates** (`datetime(2026, 1, 1)`): use `clock.now()`. Default values use `clock.now()`, so they respect fast-forward.
- **JSON:** `sa_type=JSON` (`Alert.indicator_ids`, `payload` of `AlertEvent`/`LinkMessage`/`EventLog`, `AppState.value`).
- **Enumerations as `str`:** `role`, `status`, `severity`… are stored as text (the valid values are commented on each field). Validation lives in the API schemas (FS-02), so the enums are not duplicated.
- **PK:** client UUID in `measurement`, `task_completion`, `alert`, `device` and `kudos` (idempotency); deterministic id in `task`; autoincrement integers everywhere else.
- **Indexes:** in `__table_args__`, with the exact names from data-model.md. Partial indexes use `sqlite_where=text(...)`:
  - `ux_alert_open_dedupe`: at most one unresolved alert per `dedupe_key`;
  - `ux_user_member`: a member has at most one user;
  - `ix_ruok_member_pending`: unanswered check-ins.

**Adding a table or column:** first in data-model.md, then in `models.py` (with its index if it has one), a test in `test_models.py` and `rm backend/ruok.db*` locally.

### Injectable clock (`app/clock.py`)

**Always use `clock.now()`, never `datetime.now()`.** The demo speeds up time and the whole backend must see the same time.

| Function | What it does |
|---|---|
| `now()` | Current time in UTC (timezone-aware) + the demo offset |
| `advance(seconds)` | Advances the clock (will be `/demo/fast-forward`) |
| `set_offset(seconds)` / `get_offset()` | Sets or reads the offset |
| `reset()` | Returns to the real clock |

The offset lives in memory. To survive a restart it is stored in `app_state.clock_offset_s`:
- `services.app_state.save_clock(session)` stores it; it is called by `/demo/fast-forward` and `/demo/reset` (BE-32);
- at startup, the `lifespan` calls `restore_clock(session)` to recover it.

### JSON catalogs (`app/data/`)

Domain configuration (environments, indicators, systems, interventions…) lives in JSON, **not in the code or the DB** (the *Configuration, not code* principle). Tables reference it by slug (`env_id`, `indicator_id`…).

| File | Service | Issue |
|---|---|---|
| `environments.json` | `services/environments.py` | BE-03 |
| `indicators.json`, `systems.json` | `services/catalog.py` | BE-04 |
| `protocols.json` | `services/catalog.py` (`list_protocols`) | CNT-02 |
| `task_types.json` | `services/routine.py` | BE-18 |
| `badges.json` | `services/gamification.py` | BE-19 |
| `interventions.json` | `services/catalog.py` (`list_interventions`) | BE-21 |
| `behavioral_rules.json` | `services/behavioral.py` | BE-20 |
| `crew_game.json` | `services/crew.py` | BE-23 |
| `home_message_replies.json` | `services/home_messages.py` | BE-22 |

How `services/environments.py` works (the pattern all catalogs follow):
- `load_environments(path)` reads the file and validates it with the contract schema (`TypeAdapter(list[Environment])`). `ApiModel` rejects unknown fields, so a typo in the JSON raises an error. It also rejects duplicate ids.
- `list_environments()` and `get_environment(env_id)` use an in-memory cache (`lru_cache`): the file is read only once.
- The `lifespan` loads it at startup: **if the JSON is invalid, the server does not start** (better than failing in the middle of the demo).
- Changing the JSON requires restarting the server (`--reload` only watches `.py` files).

`services/catalog.py` follows the same pattern and also performs a **cross-validation** (`check_consistency`) on load. It fails if:
- an indicator's `system_id` does not exist in `systems.json`;
- a system lists an indicator that does not exist or belongs to another system;
- an indicator does not appear in any system's list;
- an environment in `environments.json` uses an indicator that is not in the catalog.

The **ranges were reviewed in CNT-01**, with one source per row in the thresholds table of [sources.md](../sources.md#tabla-de-umbrales-cnt-01). Rule: the outer edge of the `warning` band matches the critical threshold, so there are no gaps; `test_no_gap_between_warning_and_critical` checks this. Some values are *design* choices (no published clinical threshold) and are marked as such.

If you change `indicators.json` or `systems.json`, regenerate the frontend mocks (`cd frontend && npm run gen:mocks`) as well as the types.

**Adding or changing an indicator:** add it to `indicators.json` **and** to its system's `indicators` list in `systems.json`, update the table in [sources.md](../sources.md) and `EXPECTED_INDICATORS` in `tests/test_catalog.py`. If it is for an environment, add it to that environment's `indicators` in `environments.json`. The SVG regions (`svg_region`) must match those of `BodyFigure` in the frontend.

**Adding or changing an environment:** edit `environments.json` following [environments.md](environments.md), update the table in that document and `DOC_TABLE` in `tests/test_environments.py`, and make the tests pass. Clinical values (`threshold_overrides`) are cited in [sources.md](../sources.md).

### Measurements (`services/measurements.py`)

Implements the **no data loss** principle ([offline-and-liveness.md](offline-and-liveness.md)). The frontend stores each measurement in its outbox with a UUID and resends it until the server confirms; the server must tolerate resends.

`POST /members/{id}/measurements` with `{measurements: [...]}`:

| Case | Result |
|---|---|
| new id | stored → counted in `accepted` |
| same id and same content (retry) | not duplicated → counted in `duplicates` |
| same id with different content | **409**, **nothing** from the batch is stored |
| unknown indicator, value outside `input.min..max` or `taken_at` without a time zone | **422**, nothing is stored |
| nonexistent member | **404** |

- **"Same content"** compares member, indicator, value, `taken_at` (as a UTC instant: `12:00+02:00` = `10:00Z`), `source` and `note`.
- **Atomic batch:** everything is validated before writing and there is a single `commit`. The client fixes it and resends the whole batch.
- `unit` comes from the catalog and `received_at` from the server clock (`clock.now()`).
- **Concurrent submissions** of the same batch (two tabs): if the `commit` collides on the PK, it retries once and those measurements become `duplicates`.
- The response includes the real, recalculated `assessment`. Each new measurement emits `measurement.created` (or a single `sync.batch` if the batch comes from the outbox) and auto-completes the routine tasks for that indicator (BE-18).

`GET /members/{id}/measurements?indicator_id=&from=&to=`: ordered by `taken_at`; `from` and `to` are inclusive; `from > to` → 422.

### Members (`services/members.py`)

| Endpoint | What it returns |
|---|---|
| `GET /environments/{env_id}/members` | The environment's members (from the DB, by `id`) with their `MemberSummary`. 404 if the environment does not exist |
| `GET /members/{id}` | The `Member`. 404 if it does not exist |
| `PATCH /members/{id}/privacy` | Stores `share_behavioral_details` and returns the updated member |

Where each summary field comes from (`to_summary()`):

| Field | Source |
|---|---|
| `id`, `env_id`, `name`, `position`, `share_behavioral_details`, `last_seen_at` | DB |
| `last_measurement_at` | DB (`max(taken_at)` of their measurements) |
| `liveness` | `services/liveness.py` (heartbeat, activity and environment thresholds) |
| `overall_status` | The worst of health (engine) and liveness |
| `open_alerts` | The member's unresolved alerts |

`PATCH …/privacy` can only be done by the member themselves (BE-27). Members come from the seed (`app/seed.py`), which runs at startup if the DB is empty.

### `X-Server-Time` header and CORS (`app/main.py`)

- A middleware adds `X-Server-Time` (the `clock.now()` time, ISO-8601) to **every** response, as required by [api-contract.md](../api-contract.md).
- CORS is open in development (`CORS_ORIGINS=*`). The `X-Server-Time` header is in `expose_headers` so the frontend can read it.

## Assessment engine (BE-08 … BE-11)

- **Pure functions** that receive `now=clock.now()`, the catalog and the environment, and do not touch the DB. They are easy to test.
- **Severity order:** `normal < unknown < warning < critical`. A system takes the worst of its indicators; `unknown` never counts as `normal`.
- **Freshness:** a data point older than `indicator.max_age_s` becomes `unknown`.
- **Per-environment adjustments:** `environment.threshold_overrides` is merged with the catalog ranges.
- **Escalation** (contract rule, [alerts-and-escalation.md](alerts-and-escalation.md#escalation-mode-by-level-and-delay)):
  - `self` and `crew` (and their ground equivalents) are resolved **onboard**: `realtime`, `delay_s = 0`.
  - External levels use the delay: `realtime` if it is < 5 s, `delayed` otherwise, and `autonomous` if it is ≥ 60 s **and** the status is `critical`.
- **Liveness:** `overall_status` is the worst of health and liveness (`services/liveness.py`).

## Cross-cutting conventions

- **Authentication and roles (BE-25 … BE-27):** `Authorization: Bearer <jwt>` on every endpoint except `/health`, `/auth/*`, `/system/network-info`, the read-only catalog and the emergency SOS. Routers declare the permission with `allow(...)`, `allow_member(...)` or `allow_env(...)` from `routers/deps.py`; the matrix is in `app/auth/permissions.py`. Token expiry is measured with `clock.now()`. See [auth-and-roles.md](auth-and-roles.md).
- **Device (BE-29):** requests carry `X-Device-Id`; a malformed one is ignored (it does not return 422, so it never breaks an SOS).
- **Real time (BE-28):** every state change is recorded with `events.emit()` within the change's transaction and is sent over SSE (`/events/stream`) on commit.
- **Local network and "onboard" mode (FS-08, BE-24):** `make demo` or `docker compose up` start on `0.0.0.0:8000` and FastAPI also serves `frontend/dist` (same origin, no CORS). See [control-center-and-devices.md](control-center-and-devices.md).
- **Idempotency:** every `POST` that creates data receives a client UUID; resending it does not duplicate, and the same UUID with different content returns 409.

## Contract and routers

All contract endpoints exist and are real. `tests/test_contract.py` checks that the OpenAPI and `CONTRACT_ENDPOINTS` match: if you add or change an endpoint, update the contract and that list. **Do not change the signature or the `response_model`** of an endpoint without first changing [api-contract.md](../api-contract.md).

**Defaults in the schemas:** `ApiModel` uses `json_schema_serialization_defaults_required=True`. In **responses**, fields with a default value are marked required (they are always present); in **requests** they remain optional. The frontend generates the types with `--default-non-nullable false`, so it does not force sending default values (for example, `MeasurementIn.source`).

## Exporting mocks for the frontend (FS-04)

`uv run python scripts/export_mocks.py` (or `npm run gen:mocks` from `frontend/`) calls each endpoint with the `TestClient` and generates `frontend/src/api/mocks/fixtures.gen.ts`. **It is deterministic:** the clock is frozen at `FROZEN_NOW` (14/11 10:00 UTC), so two runs produce the same file and it only changes when the data changes. If a PR shows changes in `fixtures.gen.ts` without touching data, something is using the real time instead of `clock.now()`. The data comes from the real endpoints over the demo seed. **If you add an endpoint, the frontend mocks test requires a handler for it** (`frontend/src/api/mocks/handlers.ts`).

## How to add an endpoint

1. Contract first: [api-contract.md](../api-contract.md).
2. The schema in `app/schemas/<dominio>.py`, exported in `app/schemas/__init__.py`.
3. A thin router in `app/routers/<dominio>.py` with `router = APIRouter(tags=["<dominio>"])`; the logic goes in `app/services/`.
4. Register it in `app/main.py`: `api.include_router(<dominio>.router)`.
5. Tests in `backend/tests/` using the `client` fixture.
6. `npm run gen:api` in the frontend and commit `types.gen.ts`.

## Tests

- `conftest.py` points `DATABASE_URL` to a temporary DB **before** importing the app: tests never touch `ruok.db`.
- The clock is reset before and after each test.
- The `client` fixture (`TestClient`) makes requests without starting a server, runs the `lifespan` (creates the tables and the seed) and carries an **admin** session; `vega_auth` and `medic_auth` provide headers for other roles.
